### Các điểm chưa xác minh từ bên ngoài (đã đối chiếu qua mã nguồn)
1. **Production SePay connection:** Hệ thống code hiện tại chỉ hỗ trợ `Bearer` và chưa lưu giao dịch thô. Coi như production chưa hoàn thiện kết nối SePay thật; cung cấp cơ chế vận hành thủ công hoàn chỉnh kết hợp webhook tương thích chuẩn SePay.
2. **`viettelPostService.js` auto-sync:** Đã chứng minh qua code dòng 409-413: viettelPostService gọi `handleAdminOrderAction` với action `DELIVER`. Vì vậy việc chặn ở I4 (chặn `CONFIRM/PROCESSING/SHIP/DELIVER` khi đơn BANK_TRANSFER chưa `PAID`) sẽ tự động bảo vệ an toàn cho cả luồng Viettel Post.
